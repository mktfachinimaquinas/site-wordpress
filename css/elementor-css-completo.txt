   Colado em: Elementor > Configuracoes do Site > CSS Personalizado

/* ==========================================================================
   1. ESCALA DE ESPACAMENTO
   --------------------------------------------------------------------------
   Base 8px. Toda medida de espacamento do site sai desta lista.
   Uso: padding: var(--esp-5);  em vez de  padding: 48px;

   Se a escala mudar, muda aqui e propaga para todo o CSS customizado.
   Mesma logica das cores globais, aplicada a espacamento.
   ========================================================================== */

:root {
  --esp-1: 8px;
  --esp-2: 16px;
  --esp-3: 24px;
  --esp-4: 32px;
  --esp-5: 48px;
  --esp-6: 64px;
  --esp-7: 96px;
  --esp-8: 128px;
}


/* ==========================================================================
   2. ROLAGEM SUAVE
   --------------------------------------------------------------------------
   Faz ancoras internas rolarem suave em vez de saltar. Aplicado no elemento
   raiz (html), nao no body — a rolagem da pagina e gerenciada pelo html.

   Usado pelos CTAs que levam ao formulario, como "Seja Cliente Fachini".

   A segunda regra respeita quem configurou no sistema operacional que
   prefere menos animacao. Ignorar isso pode causar nausea e tontura em
   pessoas com sensibilidade a movimento. auto e o comportamento padrao.
   ========================================================================== */

:root {
  scroll-behavior: smooth;
}

@media (prefers-reduced-motion: reduce) {
  :root {
    scroll-behavior: auto;
  }
}


/* ==========================================================================
   3. MOVIMENTO REDUZIDO — REGRA GERAL
   --------------------------------------------------------------------------
   A secao 2 respeita a preferencia do sistema apenas na rolagem. Esta regra
   estende isso a TODA transicao e animacao do site, incluindo as que o
   Elementor gera pelo painel e as que ainda serao criadas.

   Por que existe: pessoas com sensibilidade vestibular podem ter nausea e
   tontura com movimento na tela. Quem configurou "reduzir movimento" no
   sistema operacional esta pedindo explicitamente para nao receber isso.

   Por que 0.01ms e nao 0: uma duracao de exatamente zero faz alguns
   navegadores nao dispararem o evento de fim de transicao, e codigo que
   espera esse evento trava. 0.01ms e imperceptivel e mantem o evento.

   Origem: item 8.3 da revisao de blindagem de 28/07.
   ========================================================================== */

@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
/* ==========================================================================
   HEADER — Site Fachini Maquinas
   --------------------------------------------------------------------------
   Este arquivo e a fonte de verdade do CSS do cabecalho.
   O conteudo e colado em: Elementor > Configuracoes do Site > CSS Personalizado

   Classes definidas no Elementor:
     .fachini-header  container externo (barra do header)
     .fachini-logo    container do logo
     .fachini-menu    container do menu de navegacao
     .fachini-busca   container do campo de pesquisa

   CORES: usar as variaveis globais do Elementor, nunca hex literal.

   O Elementor expoe as cores globais como variaveis CSS no <body>:
     --e-global-color-primary     Navy Primario   #15274E
     --e-global-color-secondary   Cinza Medio     #5C6675
     --e-global-color-text        Onix            #0F0F0F
     --e-global-color-accent      Vermelho        #E01E26

   As personalizadas recebem ID gerado (ex: --e-global-color-5472bb2 para o
   Off-white). Conferir os nomes reais em Configuracoes do Site > Cores
   Globais, inspecionando o elemento.

   Por que variavel e nao hex: se a cor global mudar, o CSS acompanha
   sozinho. Hex digitado a mao fica para tras — mesmo problema da largura
   digitada no container em vez de herdada.

   PAR OBRIGATORIO: a secao 5 depende de scripts/header.js. As duas partes
   vivem ou morrem juntas — sem o script, o dropdown fica invisivel.
   ========================================================================== */

/* Header com fundo navy nas paginas internas.
   Na home fica transparente para flutuar sobre o hero.
   O WordPress adiciona a classe "home" ao body apenas na pagina inicial —
   por isso a negacao ancorada no body. */
body:not(.home) .fachini-header {
  background-color: var(--e-global-color-primary);
}


/* ==========================================================================
   2. HOVER DOS ITENS DO MENU
   --------------------------------------------------------------------------
   Medidas extraidas do Figma:
     padding 12px horizontal / 8px vertical
     corner radius 120px (pilula)
     fundo branco a 15% de opacidade
     altura do item 33px
   ========================================================================== */

/* Estado normal — define a forma e prepara a animacao.
   .elementor-item e a classe que o Elementor da aos itens de primeiro nivel
   (os do submenu recebem .elementor-sub-item e sao tratados na secao 4).

   IMPORTANTE: zerar o padding no painel do widget para nao somar com este.

   A altura e definida explicitamente (33px, medicao do Figma em 29/07) e o
   texto e centralizado com flexbox. Assim a altura nao depende do calculo
   padding + line-height, que e fragil e varia com a fonte.

   O padding aqui e SO horizontal — ele controla a LARGURA da pilula.
   A distancia ENTRE os itens e outra coisa: widget de Menu > Estilo >
   Espaco entre. Duas alavancas separadas para dois efeitos diferentes. */
.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .elementor-item {
  display: inline-flex;
  align-items: center;
  height: 33px;
  padding: 0 12px;
  line-height: 1;
  border-radius: 120px;
  text-decoration: none;
  transition: background-color 200ms ease;
}

/* Remove o sublinhado herdado do Theme Style tambem no hover.
   Links do site tem sublinhado por padrao; no menu isso nao se aplica. */
.fachini-header .elementor-nav-menu .elementor-item:hover {
  text-decoration: none;
}

/* Impede o deslocamento dos itens vizinhos no hover.

   O problema: a pilula do hover so existe no estado :hover, entao o item
   "cresce" quando o mouse entra e empurra os vizinhos para o lado.

   A solucao: o padding e o espaco ja existem no estado NORMAL — o hover
   apenas pinta o fundo. Como as medidas nao mudam, nada se move.
   E o que ja acontece com o padding: 0 12px acima. Esta regra garante
   que o item do Elementor nao aplique margem propria por cima. */
.fachini-header .elementor-nav-menu > li > .elementor-item {
  margin: 0;
}

/* Estado hover e foco — o retangulo translucido aparece.
   O :focus entra junto para quem navega por teclado ver onde esta. */
.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .elementor-item:hover,
.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .elementor-item:focus {
  background-color: rgba(255, 255, 255, 0.15);
}


/* ==========================================================================
   3. CHEVRON DO ITEM COM SUBMENU
   --------------------------------------------------------------------------
   A seta aparece no hover do item "Maquinas" e permanece enquanto o
   dropdown estiver aberto.

   O estado estatico sem seta e o desenho da designer, nao um esquecimento.
   O terceiro seletor da regra de baixo existe so para a seta nao sumir
   quando o mouse sai do item com o painel aberto.

   Usar opacity, nunca display:none. Com display:none o icone sai do fluxo
   e o texto "pula" quando ele aparece. Com opacity o espaco continua
   reservado e nada se move — mesmo principio da secao 2.
   ========================================================================== */

.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .sub-arrow {
  opacity: 0;
  transition: opacity 200ms ease;
}

.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .elementor-item:hover .sub-arrow,
.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .elementor-item:focus .sub-arrow,
.fachini-header .elementor-nav-menu--main .menu-item-has-children.is-open > .elementor-item .sub-arrow {
  opacity: 1;
}


/* ==========================================================================
   4. ITENS DO DROPDOWN
   --------------------------------------------------------------------------
   NAO controlar a largura do painel por CSS.

   O SmartMenus (biblioteca que o Elementor usa para menus) escreve estilo
   inline no <ul> em tempo de execucao:
     style="width: auto; min-width: 10em; max-width: 1000px"

   Estilo inline vence qualquer folha de estilo, inclusive com !important.
   A ordem de precedencia e:
     1. inline com !important
     2. inline                    <- SmartMenus atua aqui
     3. folha de estilo com !important
     4. folha de estilo normal

   Para alargar o painel, aumente o Espacamento horizontal em
   Widget de Menu > Estilo > Lista suspensa. O painel acompanha o
   conteudo, entao itens mais largos alargam o painel.
   --------------------------------------------------------------------------
   Ao passar o mouse: o item desliza para a direita e ganha um marcador
   vermelho a esquerda.

   .elementor-sub-item e a classe dos links de submenu (os de primeiro
   nivel usam .elementor-item, tratados na secao 2).
   ========================================================================== */

/* SOBRE A ESPECIFICIDADE DESTES SELETORES

   O Elementor gera CSS a partir do painel do widget no formato:
     .elementor-367 .elementor-element.elementor-element-40786ca .elementor-nav-menu--dropdown a
   Sao 4 classes. Um seletor com 3 classes PERDE para ele, mesmo vindo
   depois no arquivo — em CSS, mais especifico vence a ordem.

   Por isso estes seletores usam 5 classes. Nao e capricho: e o minimo
   para o CSS customizado prevalecer sobre o painel.

   Regra pratica do projeto: se o painel resolve, use o painel. Se
   precisar de CSS para algo que o painel nao faz, a especificidade
   precisa superar a gerada pelo widget. */

/* Estado normal do item.

   position: relative prepara o item para receber a barra, que e
   posicionada em relacao a ele. Sem isso, a barra se posicionaria em
   relacao a pagina inteira. */
.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .sub-menu .elementor-sub-item {
  position: relative;
  text-decoration: none;
  transition: transform 200ms ease;
}

/* A BARRA VERMELHA

   Em vez de border-left, a barra e um pseudo-elemento — um elemento
   gerado por CSS, que nao existe no HTML.

   Por que trocar: a borda do item herdava o border-radius de 12px do
   painel e ficava curvada nas pontas. O pseudo-elemento e independente,
   entao permanece reto.

   Como funciona:
     content: ''        obrigatorio — sem isso o pseudo-elemento nao existe
     position: absolute posiciona em relacao ao item (que e relative)
     left/top/bottom    cola na borda esquerda, com 6px de folga em cima
                        e embaixo para a barra ficar menor que o item
     width: 3px         a espessura
     opacity: 0         invisivel ate o hover */
.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .sub-menu .elementor-sub-item::before {
  content: '';
  position: absolute;
  left: 0;
  top: 6px;
  bottom: 6px;
  width: 3px;
  background-color: var(--e-global-color-accent);
  opacity: 0;
  transition: opacity 200ms ease;
}

/* Estado hover — desliza e revela o marcador.

   transform: translateX() move o elemento sem afetar o layout ao redor.
   Diferente de mudar margin-left, que empurraria os vizinhos. E o
   navegador processa transform na placa de video, sem recalcular a
   pagina — mais performatico. */
.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .sub-menu .elementor-sub-item:hover,
.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .sub-menu .elementor-sub-item:focus {
  transform: translateX(8px);
  background-color: transparent;
  text-decoration: none;
}

/* A barra aparece no hover. */
.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .sub-menu .elementor-sub-item:hover::before,
.fachini-header .elementor-widget-nav-menu .elementor-nav-menu .sub-menu .elementor-sub-item:focus::before {
  opacity: 1;
}

/* O sublinhado vem do Theme Style > Links, onde o site inteiro usa link
   sublinhado. Item de menu e navegacao, nao link de texto — por isso a
   remocao explicita nos dois estados.

   O fundo transparente no hover neutraliza qualquer cinza herdado do
   tema. O destaque visual do dropdown e o deslizar + a barra vermelha. */


/* ==========================================================================
   5. ABERTURA DO DROPDOWN POR CLIQUE
   --------------------------------------------------------------------------
   Par de scripts/header.js. O script liga e desliga a classe .is-open no
   <li>; estas duas regras traduzem a classe em visibilidade.

   Sem o script, estas regras deixam o dropdown permanentemente escondido.

   ESCOPO: --main limita ao menu de desktop. O painel do hamburguer usa
   .elementor-nav-menu--dropdown e continua com o comportamento nativo,
   onde o submenu empilha no fluxo. Se estas regras alcancassem o mobile,
   o visibility: hidden reservaria o espaco do submenu sem mostrar nada —
   um rasgo de branco dentro do hamburguer.
   ========================================================================== */

/* Estado fechado.

   Por que display: block com !important, sendo que o objetivo e esconder:

   O SmartMenus controla o painel escrevendo display no estilo inline do
   <ul>, em tempo de execucao. Enquanto ele mandar no display, o clique nao
   tem o que mostrar — o elemento simplesmente nao existe no layout.

   A saida e tirar o display das maos dele: fixamos display: block de forma
   permanente e passamos a controlar a visibilidade por opacity e
   visibility, que o SmartMenus nao toca.

   O !important e obrigatorio aqui e so aqui. Pela hierarquia documentada
   na secao 4, folha de estilo com !important e a unica coisa que vence
   estilo inline sem !important.

   visibility: hidden, e nao display: none, porque o painel precisa
   continuar existindo para a transicao de opacidade acontecer. */
.fachini-header .elementor-nav-menu--main .menu-item-has-children > .sub-menu {
  display: block !important;
  opacity: 0;
  visibility: hidden;
  pointer-events: none;
  transition: opacity 200ms ease, visibility 200ms ease;
}

/* Estado aberto — a classe e colocada pelo scripts/header.js.

   pointer-events volta para auto para os itens do submenu receberem
   clique e hover. No estado fechado ele fica em none para o painel
   invisivel nao interceptar cliques do que esta atras dele. */
.fachini-header .elementor-nav-menu--main .menu-item-has-children.is-open > .sub-menu {
  opacity: 1;
  visibility: visible;
  pointer-events: auto;
}
